## Why

- **Unblocks s2 live deployment.** The s2 `LlmCrawlPlanner` adapter
  raises `ProviderTraceMissingError` when `ProviderResponse.raw_response_ref`
  is blank — a safety property ensuring no live LLM plan is accepted
  without a durable raw-bytes audit trail. The OpenAI / Anthropic v2
  provider adapters currently do NOT populate that field, so s2
  fails-fast in production. s2.1 wires the artifact-store persistence
  that lets `raw_response_ref` be set on every successful
  `complete(...)` call.
- **Goal doc capability 1 closure.** Capability 1 ("agent planning
  loop wired into `ExternalCrawlRunner`") includes s2's LLM adapter,
  which is currently unusable live. s2.1 is the directly-dependent
  slice that closes that gap (named explicitly in the s2 plan
  Reservation 2).
- **AGENTS.md hard constraint — replay refs.** The standing rule:
  *every new non-determinism source must write a ref into the replay
  bundle AND wire the consumer in the same or a directly-dependent
  slice*. The v2 adapters introduce a wall-network non-determinism
  (the upstream LLM response bytes) that today has no persisted ref.
  s2.1 closes the producer side; the consumer side is s2's existing
  `ReplayingModelProviderV2` adapter (matches `raw_response_ref` to
  retrieve canned responses) — same-slice consumer wiring satisfied.
- **Reusability.** The same wiring serves every future
  `ModelProviderPortV2` consumer (`SchemaExtractionRuntime` in s10,
  any other LLM-backed slice in capability 3+). s2.1 builds the
  reusable plumbing once.

## Scope

### In

- **Ctor param on both v2 adapters** —
  `artifact_store: ArtifactStorePort` (from `veracrawl.ports.stores`).
  Required (raises `ValueError` when `None`); no fallback to a no-op
  store. The fail-fast posture matches s2's
  `ProviderTraceMissingError` invariant — if there's no artifact
  store, there's no way to satisfy the replay-refs rule, so the
  adapter must refuse construction.
  - `OpenAIResponsesAdapterV2.__init__(..., artifact_store=…)`
  - `AnthropicMessagesAdapter.__init__(..., artifact_store=…)`

- **Persistence call in `complete(...)`** — after the upstream HTTP
  request succeeds and the JSON body is parsed, but **before**
  building the `ProviderResponse`, persist the raw response bytes:
  ```python
  raw_bytes = response.content  # httpx Response.content is bytes
  raw_ref = self._artifact_store.write(
      raw_bytes,
      metadata={
          "provider": "openai-responses-v2" | "anthropic-messages-v2",
          "request_id": request.id,
          "upstream_id": response_id,
          "captured_at": <utc clock>.isoformat(),
      },
  )
  ```
  Then `ProviderResponse(..., raw_response_ref=raw_ref)`.

- **Captured-at timestamp via injected clock** — adapters gain an
  optional `utc_clock: Callable[[], datetime] | None = None` ctor
  param (default = `lambda: datetime.now(UTC)` when in PRODUCTION
  mode, fixture-time-fake when in FIXTURE mode). The
  `captured_at` metadata field uses this clock so replay tests can
  drive deterministic timestamps.

- **Retry-path handling** — `complete(...)` persists ONLY the
  bytes of the final successful response (the one whose
  `ProviderResponse` is returned). Intermediate retries (transient
  4xx/5xx) are NOT persisted. Rationale: retries are recoverable
  noise and the replay loop reproduces only the successful path;
  persisting transients would bloat the artifact store without
  serving replay.

- **Fixture-mode behavior** — even in FIXTURE mode (MockTransport),
  the adapter writes the raw mocked bytes to the artifact store and
  populates `raw_response_ref`. This is required for the s2
  `ProviderTraceMissingError` contract to hold uniformly across
  modes (no special-casing).

- **Tests** (red list ≥ 14 — see §Test Strategy):
  - Each adapter (OpenAI + Anthropic): persists raw bytes on
    success; raw_response_ref is non-blank and resolves via
    `artifact_store.exists(ref) is True`; ctor rejects `None`
    artifact_store; metadata fields present; retry path does NOT
    persist intermediate failure bodies; fixture-mode persists too.

- **Privacy / retention policy** — new enum
  `ProviderArtifactPersistencePolicy` (in
  `veracrawl.contracts.enums`):
  - `PERSIST_ALL` — persist every successful response (default
    for production where audit is required).
  - `PERSIST_NONE` — skip persistence; `raw_response_ref` set to
    `None` and the s2 planner's existing
    `ProviderTraceMissingError` fail-fast handles it (i.e., s2
    planner refuses to operate without a trace, by design).
  - `PERSIST_NON_SECRET` — same as `PERSIST_ALL` but
    short-circuits to `PERSIST_NONE` behavior when
    `response.headers.get("X-Veracrawl-Secret") == "true"`
    (i.e., `raw_response_ref = None` and store NOT written).
    The s2 planner's `ProviderTraceMissingError` then refuses
    the call — preserving the replay-ref invariant (no
    request is accepted if its trace is unreplayable). This
    is the **safe** outcome: we never persist secrets, and
    we never claim replay on a request whose bytes weren't
    durably stored.
  Ctor takes `persistence_policy:
  ProviderArtifactPersistencePolicy = PERSIST_ALL`. This is
  the explicit policy gate satisfying docs/07-data-contracts.md:606
  (retention) + docs/README.md:72 (privacy boundary). The
  injected `ArtifactStorePort` adapter is responsible for the
  storage-side retention policy (TTL, encryption); s2.1 only
  gates whether the bytes flow into the store at all.

- **`ReplayingModelProviderV2` extension** — add an alternative
  construction mode keyed by `raw_response_ref`:
  ```python
  ReplayingModelProviderV2(
      *,
      canned: dict[str, ProviderResponse] | None = None,
      artifact_store: ArtifactStorePort | None = None,
      canned_by_raw_ref: dict[str, ProviderResponse] | None = None,
  )
  ```
  When `canned_by_raw_ref` + `artifact_store` are both set, the
  replay adapter looks up `request.id` first; if absent and
  the original `ProviderResponse` had a `raw_response_ref`, it
  reads the bytes via `artifact_store.read(raw_response_ref)`
  and returns the pre-canned response keyed by the ref. This
  IS the in-product replay consumer keyed by
  `raw_response_ref`. Tests pin the round-trip.

- **`ArtifactStorePort.read(ref: Ref) -> bytes`** — add the
  method to the port contract. Existing implementations gain
  a thin wrapper (in-memory store: `dict.__getitem__`;
  filesystem store: `path.read_bytes()`). Raises `KeyError`
  for unknown refs. The new method has its own contract test
  (`test_artifact_store_read_contract.py`) that verifies all
  existing adapters implement the new method correctly.

### Out

- **Persistence of non-LLM HTTP responses.** s2.1 wires only the
  two v2 provider adapters. The crawl fetchers (`HttpxCrawlFetcher`,
  etc.) already persist raw HTML via `CrawlArtifactStorePort`;
  that's a separate path, untouched here.
- **New artifact-store adapter implementations.** s2.1 uses whatever
  `ArtifactStorePort` adapter the caller injects — typically the
  filesystem-backed default or an in-memory fixture in tests. The
  hashed-filesystem default lands in s15.
- **Schema-runtime / structured-output validation changes.** The
  existing `JSON_SCHEMA` refusal stays. Schema validation work is
  Phase 4 step 4.6 / s9.
- **Older v1 adapters** (`OpenAIResponsesModelProviderRuntimeAdapter`).
  Out of scope — they're being deprecated and don't feed s2.

### Shared persistence helper + same-slice replay consumer

`_artifact_persist.py` exposes TWO functions — producer + consumer
of the artifact ref, both wired in this slice:

```python
def persist_provider_response(
    *,
    artifact_store: ArtifactStorePort,
    raw_bytes: bytes,
    provider_name: str,
    request_id: str,
    upstream_id: str,
    captured_at: datetime,
) -> Ref:
    """Persist raw provider response bytes; return the artifact ref.

    Metadata schema is fixed (see §Replay invariant): all five
    fields are required, captured_at is ISO 8601 UTC.
    """
```

Both adapters call this from `complete(...)` immediately before
building the `ProviderResponse`. The helper has its own unit-test
file (test_artifact_persist_helper.py) so the contract is pinned
independently of either adapter's HTTP wiring.

**Same-slice consumer** (closes the AGENTS.md "wire-consumer-in-
same-slice" rule):

```python
def read_persisted_provider_response(
    *,
    artifact_store: ArtifactStorePort,
    raw_response_ref: Ref,
) -> bytes:
    """Read back the raw bytes for a persisted ProviderResponse.

    Raises `KeyError` if the ref is not present in the store.
    Used by replay paths (and by the s2.1 round-trip test) to
    prove that persisted refs survive the store round-trip
    byte-equal.
    """
```

The signature does NOT require `ArtifactStorePort.read` —
existing `ArtifactStorePort` has `write` + `exists` only. To
support the consumer helper, s2.1 extends `ArtifactStorePort`
with a non-breaking `read(ref: Ref) -> bytes` method (added as
an optional `@runtime_checkable` Protocol method with the
default-no-op pattern documented in §Cross-module flow).

This makes the **same-slice consumer wiring** mechanically
testable: the round-trip test asserts that
`read_persisted_provider_response` returns bytes equal to
`response.content`.

### Replay invariant

- The metadata dict written alongside the raw bytes is byte-deterministic
  given the same `(request_id, upstream_id, captured_at)` triple.
- `captured_at` is sourced from the injected `utc_clock`; replay
  tests use a fixed `datetime` to get byte-equal metadata.
- The persisted ref is included in `ProviderResponse.raw_response_ref`,
  which s2's `LlmCrawlPlanner` already records in
  `PlanDecision.replay_refs`. Therefore a future replay run that
  injects a `ReplayingModelProviderV2` keyed by `raw_response_ref`
  produces byte-equal `ProviderResponse` (same id, same text, same
  parsed_output, same usage).

### Cross-module flow

- `openai_responses_v2.py` and `anthropic_messages.py` gain a
  single new import: `from veracrawl.adapters.model_providers._artifact_persist import persist_provider_response`.
  The helper imports `ArtifactStorePort` from `veracrawl.ports.stores`.
- Adapters do NOT import any storage *implementation* — only the
  port — preserving the existing one-port-per-adapter rule.
- `ReplayingModelProviderV2` (s2's same-slice replay consumer) is
  **extended** in s2.1 (≤40 LOC behavior delta): adds optional
  ctor params `canned_by_raw_ref: dict[Ref, ProviderResponse]
  | None = None` and `artifact_store: ArtifactStorePort | None
  = None`. When both are set, `complete(request)` first looks
  up `request.id` in `canned` (legacy path); if absent, falls
  through to the `canned_by_raw_ref` path: read bytes via
  `artifact_store.read(<raw_response_ref>)`, parse them via
  the same upstream-parsing logic the v2 adapter uses, return
  a `ProviderResponse` byte-equal to the original.
  Legacy construction (`canned` only) still works — no
  breaking change for existing callers.

## Rollback

s2.1 only adds new behavior (the ctor param + persistence call).
Rollback is `git revert <s2.1-commit-range>` — but s2's planner
will then fail with `ProviderTraceMissingError` on every live call
(its existing safety behavior). The two v2 adapters can be reverted
independently if needed.

## Open Questions

1. **Metadata schema versioning**: the metadata dict has a fixed
   shape today. A future schema change would require either a
   versioned key or a re-persist migration. Default for s2.1:
   no version key; rely on the `provider` field's discriminator
   to distinguish payload shapes.
2. **Compression**: raw bytes are persisted as-is. For very large
   responses (>1 MB) compression would help. Out of s2.1 scope —
   ArtifactStorePort can apply transparent compression in its
   adapter if needed.
3. **Sensitive content (API keys in headers)**: this slice
   persists only the response body, not request headers. So API
   keys are not at risk via this path.
