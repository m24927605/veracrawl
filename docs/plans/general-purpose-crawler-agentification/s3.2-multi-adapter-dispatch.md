## Why

- **Closes capability 1 adapter-prior gap.** s3 records
  `decision.adapter_priors` (e.g., `HTTP→1.0`, `BROWSER_SNAPSHOT→0.5`)
  but the runner only uses the HTTP fetcher today. s3.2 routes
  each URL through the adapter chosen by deterministic weighted
  sampling over the priors.
- **AGENTS.md replay-stable RNG.** Weighted sampling needs a
  seed; s3.2 wires a non-blank `replay_seed_ref: Ref` ctor arg
  consumed by `random.Random(seed=stable_hash(url + ref))`.
  No wall-clock entropy — replay-deterministic by construction.
  Producer side: caller supplies `replay_seed_ref` (e.g., the
  run's `spec.id`). Consumer side: `_choose_fetcher` is a pure
  function of `(url, priors, replay_seed_ref)`. Same-slice
  producer + consumer closes the AGENTS.md rule.
- **Goal doc capability 1.** s3 was narrowed; s3.2 is the
  directly-dependent follow-up that activates multi-adapter
  routing.

## Scope

### In

- **Runner ctor change**: two new opt-in args that must both be
  set together:
  - `fetcher_map: dict[AdapterType, CrawlHttpFetcherPort] | None
    = None`.
  - `replay_seed_ref: Ref | None = None` — required non-blank
    when `fetcher_map` is set (`ValueError` on construction
    otherwise).
  Default `None`/`None` = legacy single-fetcher path (no change
  to s3/s6 callers). When set, the runner dispatches per-URL
  through `_choose_fetcher`.

- **`_choose_fetcher(item, priors, fetcher_map, replay_seed_ref, source_adapters)`** helper in
  `external_crawl/dispatch.py`:
  - Inputs: `FrontierItem`, `list[AdapterPrior]`.
  - Filter priors to those whose `adapter_type` is in
    `fetcher_map`; renormalize weights.
  - Deterministic weighted choice via `random.Random(seed=...)`
    where `seed = stable_hash(item.canonical_url + replay_seed_ref)`.
  - Returns the chosen `AdapterType`.

- **Dispatch site**: in `_fetch_with_rate_limit`, choose
  `adapter_type` via `_choose_fetcher(item, priors,
  fetcher_map, replay_seed_ref, self._spec.source_adapters)`;
  pass it to the rate-limit
  `acquire` AND to `self._fetcher_map[adapter_type].fetch(...)`.
  The rate limiter sees the chosen adapter, not hardcoded
  `AdapterType.HTTP`.

- **`spec.source_adapters` filter**: `_choose_fetcher` ALSO
  filters priors by `spec.source_adapters` — the job spec's
  declared allowed adapter list. Priors with `adapter_type ∉
  spec.source_adapters` are dropped before normalization, even
  if `fetcher_map` has them. This pins the safety boundary
  (a multi-adapter job can't accidentally route through an
  adapter the spec didn't authorize).

- **Run report additions** (keyed-always when `fetcher_map` set):
  - `adapter_dispatch_choices: dict[str, str]` — `{canonical_url:
    chosen_adapter_type}`. One entry per fetched URL.
  - `replay_seed_ref: str | None`.

- **Tests** (red list ≥ 14).

### Out

- **Multi-adapter ADMISSION rules.** Frontier admits based on
  domain/depth/budget — same regardless of which adapter
  fetches. Out of scope.
- **Dynamic adapter selection by content type.** Choice is
  made at pop time from canonical URL only.
- **Per-adapter rate limits.** Adapter implementations carry
  their own; this slice doesn't coordinate.

## Design

### Module map

```
src/veracrawl/external_crawl/dispatch.py                  # new — ≤  90 LOC
src/veracrawl/external_crawl/runner.py                    # modify — ≤  40 LOC (fetcher_map opt-in + dispatch wiring + run report)
tests/unit/external_crawl/test_dispatch.py                # new — ≤ 220 LOC
tests/unit/external_crawl/test_runner_with_fetcher_map.py # new — ≤ 220 LOC
tests/contract/test_dispatch_import_boundaries.py         # new — ≤  80 LOC
```

Behavior LOC: 90 + 40 = **130**. Under ≤ 300 cap.

### Replay invariant

- `_choose_fetcher` is pure: same `(url, priors, replay_seed_ref)`
  → same chosen `AdapterType`. The seed is derived from the
  caller-supplied `replay_seed_ref` (a deterministic string) +
  the canonical URL, so two runs with identical inputs produce
  identical adapter choices.
- `adapter_dispatch_choices` in the run report is byte-equal
  across runs with the same inputs.

### Cross-module flow

- `dispatch.py` imports stdlib (`hashlib`, `random`,
  `dataclasses`) + `veracrawl.contracts.crawl_planner.AdapterPrior`
  + `veracrawl.contracts.enums.AdapterType` + `veracrawl.external_crawl.frontier.FrontierItem`.
  No adapter imports.
- Runner takes `fetcher_map: dict[AdapterType, CrawlHttpFetcherPort]`
  — port interface only. No direct adapter imports.

## Test Strategy

Red-first.

### `tests/unit/external_crawl/test_dispatch.py`

1. `test_choose_fetcher_picks_only_available_type` — fetcher_map has
   `{HTTP}`; priors include `HTTP`+`BROWSER_SNAPSHOT`; choice always `HTTP`.
2. `test_choose_fetcher_renormalizes_weights_after_filter` —
   priors `[HTTP=0.3, BROWSER_SNAPSHOT=0.7]`, fetcher_map has only HTTP →
   HTTP picked with effective weight 1.0.
3. `test_choose_fetcher_deterministic_for_same_url_and_seed` —
   100 calls with same args → identical choice.
4. `test_choose_fetcher_distributes_across_priors_for_pinned_corpus` —
   pinned URL corpus of 10 specific URLs (e.g.,
   `https://a.example/0` through `/9`); priors `[HTTP=0.5,
   BROWSER_SNAPSHOT=0.5]`; expected choice list is hardcoded
   per-URL (deterministic given the seed + hash function).
   Assert exact match — no statistical bounds. Demonstrates
   both adapters are reachable; corpus picked offline so
   both appear at least once.
5. `test_choose_fetcher_pure_function_no_global_state` —
   call with arg A, then arg B, then arg A again — A's
   choice unchanged.
6. `test_choose_fetcher_rejects_empty_priors` — `ValueError`.
7. `test_choose_fetcher_rejects_empty_fetcher_map` — `ValueError`.
8. `test_choose_fetcher_rejects_blank_replay_seed_ref` —
   `ValueError(match="replay_seed_ref")`.
9. `test_choose_fetcher_handles_no_matching_priors` —
   priors=[BROWSER_SNAPSHOT=1.0], fetcher_map={HTTP} → `ValueError`
   (no adapter available).
